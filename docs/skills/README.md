# Codex 技能设计与使用

当前目录是设计说明，没有已安装的项目技能。仅有重复且已验证的工作流才值得整理为技能；项目事实放架构和开发文档，长期规则放 AGENTS，单次实施步骤放计划。

## 候选工作流

| 候选 | 适用触发 | 预期输出 |
| --- | --- | --- |
| 定向 Maven 验证 | 修改 Java 后选择并运行相关测试 | 实际命令、目标执行数量、失败原因和限制 |
| Mapper 契约检查 | 新增或修改自定义 Mapper/动态 SQL | 绑定、参数、范围、分页和 SQL 验证清单 |
| CRUD 迁移核对 | 修复审计、ID 回填或批量插入 | 调用链、行为变化和对应回归证据 |

这些是待建设建议，不宣称已生效。

## 技能结构

官方定义技能目录包含 `SKILL.md`，其中有 `name`、`description` 元数据及任务指令，可附带脚本和参考材料。[官方技能文档](https://learn.chatgpt.com/docs/build-skills)

描述应简短说明何时使用及边界；正文定义输入、前提、关键选择、验证和交付，避免重复通用代理规则。只有稳定且必要的过程才固化，不为每个项目类创建技能。

Codex 的仓库技能发现位置为 `.agents/skills/`，本目录不会自动注册。实际启用应确认运行环境允许写入及客户端加载结果，不以 Markdown 宣称安装完成。不在本任务中修改用户级技能或配置。

## 验收

用代表性任务检查触发准确性、目标测试非零、失败诊断和报告，确保不会默认访问真实平台、提交或发布。版本或环境变化时更新引用，不把机器专属路径固化进技能。
