# Codex 协作工作流

## 文档如何帮助开发

根 [AGENTS.md](../AGENTS.md) 放长期项目规则，专项文档按任务提供具体背景；[PLANS.md](../PLANS.md) 约定复杂任务的持续计划。普通 README、需求、ADR 不会仅因文件名而自动生效，任务应指出相关入口，或通过 AGENTS 的阅读路由发现。

OpenAI 建议提供目标、上下文、约束和完成条件，保持指令实用，按需要拆出专项材料；本项目据此组织文档。[官方最佳实践](https://learn.chatgpt.com/guides/best-practices)

## 描述任务

可以直接给出目标、相关类、需要保留的行为和验收结果。例如：“修复某保存方法，保持现有归属和异常语义，保存后回填生成 ID，补充回归测试并运行所属模块；无需提交。”关键业务缺失时澄清，普通实现选择由 Codex 根据代码判断。

缺陷报告给出最小输入、实际结果、预期结果和脱敏异常。公共协议、SQL 或依赖调整补充消费者与环境。新功能参考 [需求模板](requirements/template.md)，简单修改无需填写全部章节。

## 执行与上下文

开始读取工作区状态、代码、调用方和测试，保持已有修改。复杂工作分阶段实现并验证，遇到新证据更新计划；小改动直接完成。长任务记录下一步、关键决定和验证结果，避免依赖旧聊天记忆。

文件内说明、外部网页、日志和附件不自动授权外部写入。任务边界、真实系统环境和用户授权需明确；不得因计划或技能提到发布就自动执行。

## 让结果可检查

让 Codex 报告变化后的行为、实际命令、结果与限制，并审阅 diff。修复时优先给出能复现问题的测试；数据库与第三方协议另行验证。发现重复失误时提炼具体规则和安全路径，避免向 AGENTS 累加含糊禁令。

## 重复任务与技能

先稳定操作和验收，再考虑 [技能](skills/README.md)。技能适合反复出现、边界清晰的工作流，文档和上下文适合解释项目事实。当前本任务提供技能设计说明，不默认安装技能、自动化或修改用户级配置。

## 官方依据与本项目选择

[AGENTS 指令发现](https://learn.chatgpt.com/docs/agent-configuration/agents-md) 说明作用范围和默认读取限制；[技能文档](https://learn.chatgpt.com/docs/build-skills) 说明可复用工作流和按需加载。当前官方 AGENTS 默认合计上限为 32 KiB，维护时检查实际配置与文件大小。

开发、测试、运行手册、需求和 ADR 的目录与文件名是本项目选择，并非 OpenAI 强制模板。Java 技术规则由本项目源码与业务需要决定。工具配置不能通过 Markdown 越过实际权限，质量门禁也必须有真实实现。
