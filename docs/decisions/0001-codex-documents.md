# 0001：Codex 规则与专项文档分工

状态：已采纳。日期：2026-10-13。

## 背景

项目已有详细 AGENTS.md，但开发、测试、架构、需求和计划缺乏导航，工程现状入口缺失。将所有解释继续堆入代理指令会增加重复和维护成本。

## 决策

保留现有 AGENTS.md 的业务规则，增加按任务阅读的专项文档导航。PLANS.md 定义复杂任务计划，需求和 ADR 分别记录行为和长期取舍。仅面向 Codex，不增加其他代理专属文件。本次不安装技能或改变工具权限。

## 方案比较

仅扩写 AGENTS 会使长期规则与操作材料混杂；建立大量模块指令又会引入重复。当前采用根规则与集中专项文档，后续只有模块规则明显不同才增加更深层 AGENTS。

## 后果与验证

阅读入口明确，代价是代码变更必须同步相关文档。普通文档需按任务读取，不假定自动加载；核心检查仍放根规则。本次以本地链接、引用路径、命令语法和差异检查验证，文档不证明业务已通过测试或平台集成已成功。

本选择参考 [OpenAI 最佳实践](https://learn.chatgpt.com/guides/best-practices)，具体目录与文件名由本项目决定。若出现重复维护或规则过长，应逐项去重并核对指令加载大小，不能删除关键业务约束。
