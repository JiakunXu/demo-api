# 代码风格约定

状态：项目文字规范；尚未配置统一自动格式化门禁。维护于 2026-10-13。适用于手写 Java 主代码和测试，保持范围清楚。本文定义规范，不代表本次已生成 IDEA 配置或执行全库格式化。

## 基本布局

| 内容 | 项目约定 |
| --- | --- |
| Java/POM | 4 空格缩进；Java 不混用 Tab |
| YAML | 保持文件既有层级缩进；本批不修改配置内容 |
| Mapper XML | 延续 Tab 层级及 SQL 对齐，特殊规则见持久化文档 |
| 字符与文件 | 新增文本使用 UTF-8，正常文件末尾换行，去掉无意义行尾空白 |
| Java 行宽 | 新增/修改的手写代码以 100 字符为目标，长 import、字符串/URL 和不可安全拆分的内容可例外 |
| 大括号 | 左括号与声明同一行；if/else/循环使用块，不为压行省略括号 |
| 空行 | 方法、逻辑段落合理分隔，不堆叠无意义空行 |
| 续行 | 优先清楚的参数/条件边界，延续 4 空格续行或现有参数对齐，不混合多种布局 |

100 字符是本项目新增的书写目标，不是 OpenAI 强制 Java 标准或已执行的检查。旧文件只修改与当前任务相关的部分；第三方来源代码、自动生成文件或特殊文本块不批量重排。

## import 与声明

同组 import 保持字典序。延续项目常见布局：第三方及项目包为一组，java/javax 为一组，静态 import 为一组，组间空行。新增代码优先显式 import，不使用通配符；不为风格清理整个历史文件。Jakarta 是真实包名迁移问题，不按 Java 前缀全局替换。

字段、参数和链式调用对齐以可读性与周边风格为准，不为形成列对齐扩大无关修改。不使用重新排序类成员来夹带行为变化。Lombok 使用约定见 [Java 开发](java-conventions.md)。

## 换行与注释

较长条件在逻辑运算边界分行，较长调用在参数或链式方法边界分行，不手工分割字符串造成协议变化。注释解释原因、限制、时序或异常条件，避免重复方法名称；公共契约、单位和空值语义变化时同步注释与文档。

代码块示例保留语言标记，Markdown 不把普通源码变成转义文本。Mapper 的 CDATA、动态标签和缩进按 [持久化规则](persistence.md) 单独处理，不套用 Java 布局。

## 工具与验收边界

统一工具配置及其 IDE/CI 接入属于后续实施，本批仅建立文字规范。配置确定前不能宣称自动格式化可复现或质量门禁已存在。格式化后审阅 diff、确认没有字符串/注释/SQL 语义变化；纯格式修改无需增加业务单元测试。
