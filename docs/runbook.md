# 运行与故障排查手册

维护于 2026-10-13。本仓库没有统一生产部署脚本或已验证的健康检查接口；以下为本地打包、启动和定位步骤。上线按实际环境与授权另行确定。

## 打包和启动

先完成相关验证，确认目标配置与依赖；从仓库根目录执行：

```bash
./mvnw -pl start -am -DskipTests package
java -jar start/target/start-1.0.jar
```

核对实际产物名再启动，`-DskipTests` 不提供测试通过证据。当前仓库配置为 `127.0.0.1:8080`，外部覆盖可能改变绑定。无需对外访问时保留本地范围，不盲目改成公网绑定。

启动前检查数据库结构、Redis 序列化、注册/配置中心、消息组件、任务配置和使用功能的证书。完整配置入口见 [开发环境](development.md)。不要仅因为启动端口开放就认为关键业务可用。

## 定位顺序

1. 保留脱敏的环境、提交、命令、时间和第一个有效异常。
2. 分清依赖解析、编译、测试、配置绑定、Bean 初始化和运行期业务失败。
3. 按异常中的配置键和类读取代码；不要公开完整配置值。
4. 复现最小问题，修改后运行与其相关的验证。
5. 报告剩余限制，不通过吞异常或关闭安全控制制造启动成功。

| 问题 | 重点证据 |
| --- | --- |
| MQTT 初始化失败 | ProducerBean 中端口/实例/域名及外部服务条件 |
| Mapper 未绑定 | namespace、方法 id、XML 资源打包和 mapper-locations |
| 查询异常或结果不一致 | 参数、数据范围、软删除、真实 SQL、隔离库结构 |
| Redis 行为异常 | 缓存缺失/过期区别、默认序列化、TTL 和旧数据兼容 |
| 日志错误但测试成功 | surefire 报告及预期异常断言 |
| 数据已写但消息失败 | 事务边界、发送时序、补偿与业务幂等 |

## 发布和回退

发布记录应包含版本、构建来源、验证、配置变动、数据库迁移次序、观察指标及回退条件。无正式指标体系时明确采用的验证信号，不能编造监控已配置。

回退前核对数据库和协议兼容性。代码回退不能自动撤销迁移、已发送消息或支付动作；逐项说明补偿。不得未经授权直接操作真实数据库、删除 Redis 键、重投消息或发布。
